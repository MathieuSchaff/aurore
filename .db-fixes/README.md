# One-off database fixes

Use this directory for reviewed, idempotent SQL corrections that cannot be regenerated by an
existing runner. Do not patch derived data such as linker results, auto-tags, canonical keys, or
dermatology profiles: fix their emitter and re-derive them instead.

Every fix must start with its triage decision:

```sql
-- Root cause: <why the stored data is wrong>
-- Why data-fix: <why no maintained runner owns this correction>
-- Re-derive: <what must be recomputed after the fix, or none>
```

Apply the same file in this order:

1. Run `just db-fix .db-fixes/<name>.sql` against dev.
2. Review the SQL and its reported counters.
3. Run `TARGET=prod just db-fix .db-fixes/<name>.sql` from the laptop and confirm the prod prompt.

`db-fix` executes the whole file in one transaction and stops on the first SQL error. A successful
dev run keeps the file for review. A successful prod run moves it to `.db-fixes/applied/` with a
timestamp so it cannot be replayed accidentally. Always inspect the counters: a zero-row fix is
still successful and is archived.

See [`docs/commands/deploy-ops.md`](../docs/commands/deploy-ops.md#data-fixes) for the complete
operational contract.
